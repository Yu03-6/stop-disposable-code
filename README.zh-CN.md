# Stop Disposable Code · 停止一次性代码

[English](README.md) | 简体中文

一个帮助 AI 持续维护和扩展代码项目的 Codex 技能，减少重复业务规则、凭猜测添加的补丁，以及只存在于聊天记录中的项目知识。

**先澄清需求，再检查可维护性；修改完成后，用实际验证确认结果。**

## 为什么需要这个技能

功能今天能运行，不代表明天容易修改。这个技能要求 AI 在动手前理解现有实现、明确回退方式、规划有效验证、把必要知识留在项目中，并处理问题根因，避免不断叠加补丁。

主要适用于修改已有功能、扩展功能、修复 bug 和重构代码。纯解释性问答、独立的文案或素材修改，通常不属于自动选用范围。

## 有疑虑就询问，不猜测需求

只要 AI 对用户希望修改的内容有疑虑，或发现需求描述有歧义，就必须直接询问用户；得到答复前，不能实施依赖该答案的修改。

例如，“让用户保持登录的时间更长”没有说明具体时长，也没有说明是否适用于所有设备。AI 应当先询问这些要求，不能自己选一个时长就修改登录逻辑。

AI 必须遵守以下规则：

- 说明具体不确定之处，提出简洁、明确的问题。
- 得到用户答复后，才能开始依赖该答案的修改。
- 不把用户沉默、等待时间或建议的默认选项当作确认。
- 等待期间，只继续不依赖该答案的独立工作。
- 沿用用户已经明确给出的决定，不反复询问已解决的问题。
- 实施或验证过程中出现新的需求歧义，同样先询问再继续相关工作。

技术事实应通过阅读代码或针对性诊断查明；用户期望的产品行为应向用户确认。当预期结果已经明确时，内部实现细节可以沿用项目现有约定。

## 修改前的五项检查

| 检查项 | AI 需要确认的内容 |
| --- | --- |
| 理解现有实现 | 相关代码路径、业务规则和状态由哪里统一负责、哪些逻辑可以复用、哪些行为必须保留。 |
| 限定范围与保留回退方式 | 明确本次修改边界，保护用户已有的无关改动，并确定适当的审查和回退方式。 |
| 验证功能与回归影响 | 明确可观察的成功标准、相关旧功能的验证方法，以及暂时无法满足的运行验证条件。 |
| 将必要知识保存在项目中 | 判断哪些启动、配置或设计说明需要更新，让后续维护不依赖聊天记录。 |
| 修复根因与清理旧逻辑 | 找出 bug 根因的证据，或明确功能修改替换了什么规则，并识别应删除的过时逻辑。 |

每项检查都需要标明：已就绪、不适用并说明原因，或因具体前提缺失而受阻。在修改实现代码之前，AI 会简要汇报检查结果。这是 AI 根据证据进行的自检，不要求用户逐项批准五个检查项。

确定验证计划不代表测试已经通过。实际验证在实施后执行，完成报告必须区分已通过、失败和未执行的检查。

## 安装

可以直接向 Codex 发送：

```text
使用 $skill-installer 安装 https://github.com/Yu03-6/stop-disposable-code 中的技能，技能位于仓库根目录。
```

手动安装时，将 `SKILL.md` 和 `agents/` 目录一起复制到当前 Codex 环境支持的技能目录下，并将技能文件夹命名为 `stop-disposable-code`。具体发现机制和安装位置请参阅 [Codex 官方技能文档](https://developers.openai.com/codex/skills/)。

## 使用

明确调用示例：

```text
使用 $stop-disposable-code 修改订阅取消流程。
如果需求有任何不明确的地方，先询问我，再修改依赖该答案的代码。
```

`agents/openai.yaml` 已开启自动选用，技能描述覆盖功能修改、功能扩展、bug 修复和重构。是否自动选用由模型判断，不能保证每次符合条件的请求都会触发；需要确保选用时，请明确写出技能名称。

技能指令使用英文编写，提问和进度汇报应使用用户的语言。

## 适用边界

这个技能不要求：

- 重写项目、引入复杂架构，或为假想的未来需求增加抽象层。
- 为每个小改动增加测试框架或架构文档。
- 自动提交、推送、重置代码，或暂存无关改动。
- 对已明确的需求反复请求批准，或审计整个仓库。

技能遵循适用的项目指令和用户授权范围。它是一套工作指令，不是静态分析工具，也不能保证生成的代码完全没有 bug。
